Movie Ticket Booking System · Full-stack web application

← Open CineSeat

This is an academic cinema simulation. The application has a deployed frontend, server API and persistent shared database. Theatres, show schedules, screen formats, prices, payments and admission tickets are demonstrations. No real payment or cinema booking is processed.

What the project does

Discover

56-film collection with posters, thumbnails, cast and director information, search, genre/language filters, official teaser links where verified, and source-linked release announcements.

Choose the experience

Three demo theatres, dates and fixed performances. Compare language, subtitles, 2D/3D, HD/2K or 4K projection and Dolby audio before choosing seats.

Book together

Classic, Premium and Recliner seats, best-seat suggestions, up to 8 seats per performance and 8 performances per order. One bag, snacks and a promotional discount.

Manage your night

Authenticated ticket history, printable/downloadable tickets, receipts, order cancellation, simulated refunds and FIFO group waiting lists.

Community & worldwide

Account-based favourites, hype votes and editable ratings. Separate Simkl worldwide day/week/month trending lists with cache timestamps.

Owner administration

Owner-only movie management, booking overview, CSV exports and recording simulated counter payments. No shared admin password.

Architecture

LayerImplementation
FrontendReact/Vinext shell; responsive HTML, CSS and JavaScript booking interface.
BackendCloudflare Worker API. Validates identity, movie, performance, seat capacity, current price, ownership and request origin.
DatabaseD1 SQL with Drizzle schema migrations. Profiles, movies, orders, bookings, unique seat claims, waiting lists, ratings, votes, favourites and feed cache.
AuthenticationPlatform-managed Sign in with ChatGPT. User identity comes from trusted server headers. Administrator access uses a secret owner-email setting.
External informationSource-linked film metadata and release snapshot. Live Simkl trends are cached server-side; stale data is explicitly labelled.

Data structures and algorithms

Arrays and filteringCatalogue search, genre/language filtering, bag selections and sorted rankings.
Sets and mapsDetect duplicate seats; index movie preferences; track unavailable seats.
FIFO queueWaiting groups are processed in arrival order. A head group waits until sufficient seats are free; smaller groups cannot jump ahead.
Seat recommendationEnumerates adjacent groups in a row and scores them by distance from the central viewing area. Falls back to nearby split seats and warns the user.
Atomic transactionAll performances in one order commit together. A unique (performance, seat) key prevents the same seat being sold twice. Any conflict rolls back the entire order.
IdempotencyA checkout request key prevents duplicate orders when the same request is retried.

Suggested 5-minute demonstration

  1. Open Discover and show thumbnails, posters, search, cast/director and community ratings.
  2. Open This week’s releases and Upcoming. Explain the source-linked release snapshot.
  3. Open Worldwide hype and switch between day/week/month. Explain Simkl trends versus CineSeat community points.
  4. Select a film, compare the three theatres and filter language, subtitles, picture format or sound.
  5. Choose a future performance. Select a recliner, compare its price with Classic, and use group seat suggestions.
  6. Add a second movie/theatre to the bag. Sign in, add a snack and apply MOVIENIGHT.
  7. Confirm the simulated checkout. Open the receipt and ticket to show theatre, screen, seat class and format.
  8. Cancel the complete order and show the updated ticket status. Explain automatic FIFO waitlist allocation.
  9. Use the owner's account to show administration and CSV export. Never display environment secrets.

Recording: use 1920×1080 or higher resolution, browser zoom around 100–125%, visible mouse pointer, and close unrelated windows. Voice-over is optional; keep text and outputs readable.

Validation

Automated checks cover authentication, administrator authorization, private booking history, price tampering, duplicate seat rejection, whole-order rollback, repeat checkout, theatre-scoped inventory, recliner pricing, experience snapshots, editable ratings, cancellations, FIFO allocation and counter settlement. Frontend script smoke tests check the principal views. See the project README for test commands and verification limits.

Scope and honest limitations

  • Real payment gateways, cinema inventory, email and SMS services are not connected.
  • Public browsing is available; booking, ratings and saved preferences require ChatGPT sign-in.
  • New film announcement dates are an attributed snapshot and may change. Upcoming films are not falsely offered as available to book.
  • The catalogue includes older films as demo screenings. Some runtime slots and dubbed/3D variants are demonstration values.
  • Ratings begin with real user votes; no IMDb score or fabricated audience activity is seeded.
  • Tickets are project artifacts, not admission passes. Older browser-only test accounts are not imported.
  • Film artwork belongs to its respective rightsholders and is used here to identify films in an educational demonstration. Follow source links for attribution.
